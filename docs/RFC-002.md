# LOLA OS — Technical RFC-002

**Document ID:** LOLA-RFC-002 · **Version:** 0.1 · **Date:** 2026-11-10
**Status:** Accepted (supersedes LOLA-RFC-001 of 2026-11-08)
**Product:** LOLA — decision-first, edge-first agentic OS for trading

---

## 1. What LOLA OS is

LOLA is an operating system in the literal sense: a kernel that owns
scheduling, memory, I/O boundaries and protection rings, whose "programs"
are trading decision paths and whose "filesystem" is a decision ledger.

| OS concept | LOLA implementation |
|---|---|
| Kernel | `lola-core`: event bus, scheduler, contracts, risk guard |
| Memory | SQLite ledger + knowledge graph + curated memory (`docs/MEMORY.md`) |
| Device drivers | Venue adapters (Hyperliquid now, Nado later) and model backends |
| Syscalls | Versioned contracts: `MarketStateV1`, `DecisionV1`, `OrderIntentV1` |
| Processes | Decision paths (deterministic → d1 → agent escalation) |
| Protection ring 0 | Deterministic risk engine — models live in ring 3 |

The defining principle, unchanged from RFC-001: **don't solve the same
problem twice.** Retrieve known answers, reuse validated decision paths,
and spend inference only where it creates value. What changed is everything
around that principle — see §9 (what RFC-001 got wrong).

## 2. Locked decisions

All decisions below were interrogated and locked with the owner on
2026-11-10. Full context and rejected alternatives: `docs/DECISIONS.md`.

| # | Decision |
|---|---|
| 1 | Rust core, single process, **no sidecars**, mobile constraints from day one |
| 2 | Own nano-RIPL inference layer (inspired by llama.cpp/RIPL/Hermes/Pi — never forked), validated against an in-process reference oracle |
| 3 | NautilusTrader dropped from v0.1; conservative replay engine lives in `lola-replay` |
| 4 | Hyperliquid first (official Rust SDK): perps + spot, leverage 1–10x in schema; Nado (Inchain) designed-for, built later |
| 5 | Execution: paper → **testnet** (leverage free) → mainnet via **evidence-gated leverage ladder** (1x→2x→5x→10x) |
| 6 | d1-2B (decision) + LFM3-1.7B (agent) at 4-bit; profile-based residency |
| 7 | Memory: immutable core + TTL'd bulk; canonical facts + append-only ledger; no vectors in v0.1; similarity = bucket signature + bounded kNN |
| 8 | Ruthless cut: LOLA harness first, one venue, Experiment A only |
| 9 | Key management and UI/UX are carved-out discussions — zero assumptions encoded |

## 3. Scope

**In (v0.1):** Hyperliquid testnet · BTC/ETH perps + one spot pair ·
5m primary / 1h context bars · paper + testnet execution · d1-2B +
LFM3-1.7B · decision ledger, graph, retrieval · experiment ladder A0–A3.

**Out (v0.1, revisit later):** mainnet · Nado adapter · equities/ETFs ·
strategy discovery (B ladder) · specialist models (VL/Audio/Omni/Base) ·
online weight updates · news as primary signal · sub-second/HFT claims.

## 5. Kernel contracts

Three versioned contracts carry everything (`crates/lola-core/src/contracts.rs`):

- **`MarketStateV1`** — deterministic feature state, *not* raw market
  streams. Two timestamps on every record: `event_time_ns` (when the market
  event occurred) and `ingestion_time_ns` (when LOLA saw it). Backtests must
  never conflate them.
- **`DecisionV1`** — typed answers + probabilities in LOLA's schema, never a
  backend's raw output. Malformed output fails closed to `ABSTAIN`.
- **`OrderIntentV1`** — a *proposal*, never an authorization. Carries
  `requested_leverage` which the risk engine may clamp down, never up.

Rules that admit no exceptions:

1. **Completed bars only.** Every feature is computable from bars that
   closed at or before `event_time_ns` (lookahead audit in S7).
2. **Models never authorize.** Only the deterministic risk engine can.
3. **Cache hits never bypass risk.** Retrieval accelerates decisions;
   it cannot skip ring 0.
4. **Decision-cache invalidation:** a hit requires exact snapshot hash +
   feature schema + strategy version + model checkpoint + adapter version +
   policy version + instrument + timeframe. Any change invalidates.

## 6. Risk engine (ring 0)

Deterministic, independent of both models, **fail-closed**. Check list is
fixed in `lola-core::risk::CHECK_NAMES` (eligibility, leverage-within-policy,
margin, cash, concentration, per-instrument and portfolio exposure, daily
loss, drawdown, spread, liquidity, data freshness, venue availability,
reduce-only validity, idempotency).

Leverage (ADR-008): the schema supports up to 10x. Testnet may run any
leverage (it exists to gather liquidation/funding/calibration data).
Mainnet starts at 1x and unlocks rungs only through versioned policy
changes backed by measured evidence — evaluated offline by humans, never
by the models.

## 7. Decision paths

```
bar closed → MarketStateV1 → retrieval
   ├─ exact cache hit (valid deps) ────────────► risk engine
   ├─ deterministic rule fires ────────────────► risk engine     (no model)
   ├─ d1-2B: regime + candidate assessment ────► risk engine     (shadow first)
   └─ escalate → LFM3-1.7B agent: research,
      investigate novelty, explain conflicts      (never candle-critical)
```

d1 runs in **shadow mode first** (ADR-015): it classifies real candles and
its calibration (ECE/Brier per regime label) is measured before it is
allowed to accept or veto anything. d1 probabilities are model
probabilities, not trade-profit probabilities.

## 8. Venue abstraction

`lola-venue::Venue` is the driver boundary. The Hyperliquid adapter (S6)
wraps the official `hyperliquid-rust-sdk` (REST + WS, EIP-712 signing).
Nado (Inchain) later implements the same trait. The full streaming and
order-placement surface is extended — not rewritten — in S6/S8, shaped by
what integration actually requires rather than speculation.

## 9. What RFC-001 got wrong (and what changed)

1. **The backlog contradicted its own principle** — "prove it deserves to
   exist" followed by 12 epics, 7 models, 2 asset classes. v0.1 is a
   ruthless cut.
2. **"Python first"** died: Rust core, no sidecars, mobile from day one.
3. **Spot-only/no-leverage** died: Hyperliquid perps + spot, 1–10x with an
   evidence-gated mainnet ladder. The risk engine grew margin, funding and
   liquidation responsibilities.
4. **"Low latency" was undefined.** Now it's budgets (§10).
5. **d1 competence was assumed.** Now it's shadow-mode-first with a
   calibration gate.
6. **The schema invited over-storing** (fat JSON blobs in hot tables).
   Now: lean rows + content-addressed blobs + TTL compaction
   (`docs/MEMORY.md`).
7. **NautilusTrader** carried Python and desktop assumptions that contradict
   the edge goal. Dropped; its conservative-fill philosophy lives on in
   `lola-replay`'s defaults.

## 10. Latency budgets

Measured from day 0; every number is a budget, not a promise.

| Path | Budget | North star |
|---|---|---|
| Retrieval (signature + bucket + kNN) | < 10 ms | — |
| Risk checks (all 15) | < 1 ms | — |
| d1 structured decision (warm) | < 200 ms | 50 ms (RIPL-class) |
| Decision loop end-to-end (p95, 5m cadence) | < 1 s | — |
| Model cold load | < 5 s | — |
| Warm in-process swap (page-cache reload) | < 1 s | — |

## 11. Mobile constraints (apply to every slice)

Single process, no fork assumptions · bounded memory with explicit budgets ·
GGUF-compatible weight container · SQLite on local storage only ·
no runtime dependency that cannot build for aarch64 Android later ·
Compose Multiplatform / Kotlin named as the future UI direction
(`docs/UI_UX.md` — nothing designed yet, by decision).
